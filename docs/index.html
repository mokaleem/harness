Internal and external apply to every capability

Skills, MCP tools, agents and subagents can each come from an internal team or an external provider. Origin is independent of where the capability runs: an internal agent can be a remote corporate service, and a vendor-authored worker can run inside DeerFlow.

CapabilityInternal exampleExternal exampleSetup guide
SkillTelecom team’s approved site-performance workflowVendor or open-source workflow packageSkills
MCP toolsCorporate BQ/catalog service, local or remoteVendor MCP endpoint or installed server packageMCP tools
AgentRAN Analyst in DeerFlow or a corporate NOC agent serviceVendor-supplied agent instructions or independently running agentAgents
SubagentInternal metrics reviewer, native or service-backedVendor-authored native worker or separately invoked specialistSubagents

Native configuration, MCP and ACP are integration mechanisms; they are not internal/external ownership categories. Origin does not itself create a permission boundary.

DimensionExamplesWhat controls it
OriginYour telecom team / vendor / open-source projectSource review and pinned releases
OwnershipOne user / deployment-wide definitionsStorage and management APIs
SelectionAgent skills, MCP installation IDs, allowed subagentsAgent configuration
AuthorizationWho may discover, activate or execute a resourceAuthenticated identity and authorization provider

The opt-in enterprise extension adds team membership, immutable capability releases and reviewed skill publication. See Enterprise services for installation and deployment boundaries. User ownership and deployment-wide configuration also exist in the core application.

Before following a guide

  1. Configure a working checkout with Python 3.12+, uv, the frontend prerequisites and a usable model. The root setup flow is make setup; the manual sequence is below.
  2. Run the application through its unified entry at http://localhost:2026. Use an authenticated account with the management permissions required by each guide.
  3. Install packages and command-line programs in the environment that actually executes them: Gateway Python, an MCP subprocess environment, or a sandbox image. These are different environments.
  4. Replace illustrative URLs, IDs, model names and filesystem paths before using the examples. Merge configuration snippets into existing files; do not overwrite other entries.
Shell · repository root
make config
make install
make dev

Use the repository’s supported shell/toolchain for make. Python packaging commands and JSON payloads are also provided where appropriate. JSON API examples show request bodies, not a bypass of authentication or CSRF requirements.

Documentation baseline

Source baseline: 4c05e88c. Application: 2.2.0-dev; harness package: 2.1.0; public extension API: 0.2.5. This handbook describes the local implementation. Examples that require a service or package are identified; the enterprise workflow was verified with synthetic services; production integrations require operator configuration.

Open docs/index.html directly. All handbook navigation and styling work offline. To browse source links over HTTP, serve the repository root with python -m http.server 8765 --bind 127.0.0.1, then visit http://localhost:8765/docs/.
