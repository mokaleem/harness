Enterprise services around the harness

The enterprise package owns capability governance. DeerFlow continues to own the agent loop. Read the native setup and API contract guide before enabling it.

1. Authoritative capability registry

Skills, agents, subagents, Python tools and MCP servers share one versioned registry. Each can be internal or external. Immutable revisions record ownership, exact dependency versions, content digests and activation state.

One team deployment consumes a generated runtime projection. Multiple teams share the same registry database. SQLite supports local development; PostgreSQL shares state across nodes. Typesense metadata is exported from this registry and remains a replaceable discovery index.

2. Create a skill

  1. Click Create a skill after a conversation completes.
  2. Capture authenticated run references, receipts and content hashes in an expiring draft.
  3. Write a reusable recipe with parameters, examples, query resources and approved table DDL references.
  4. Validate parameters and package structure with native SkillScan, then run the deployment's domain validator.
  5. A different administrator reviews the exact validated digest.
  6. Publish an immutable version; activate and deploy it separately.

For a telecom site-health recipe, parameterize the date and site identifier. The validator should check approved identifier mappings, schema freshness, query permissions, dry runs and expected behavior. It should not assume a correct join from matching column names.

3. Failure handling

Explicitly idempotent async calls can retry within attempt and time budgets. Shared circuit state admits one recovery probe after cooldown. Permission and validation failures do not retry. Ambiguous writes are never automatically replayed.

The model receives a dependency failure receipt and escalation ID, retains earlier verified results, and explains missing evidence. Operators see the escalation queue in Skill releases.

4. Approved remote execution

The remote adapter requires an operator-approved HTTPS broker and an identity-bound policy receipt. The remote service enforces filesystem, network, CPU, memory, disk, command deadline and lease lifetime limits. It supplies read-only skills and bounded file transfer.

The adapter rejects weakened receipts and path escapes. It provides no local execution fallback. This change supplies the adapter and protocol; it does not provision or certify your company's remote infrastructure.

Native setup and upgrade compatibility

Install the enterprise package with DeerFlow's extension manager, configure registry credentials through environment variables, register team memberships and capabilities, then deploy a projection. The setup guide includes PowerShell and macOS commands, a telecom MCP example, the domain validation contract and the remote broker protocol.

Extension API 0.2.5 adds narrow evidence and execution contracts. Existing observational extensions retain their defaults. The enterprise package contains no copied agent engine.

Integration boundariesProduction BigQuery validation, PostgreSQL contention checks, Typesense indexing and remote broker enforcement require tests against your approved services. The committed tests and browser checks use synthetic data.
