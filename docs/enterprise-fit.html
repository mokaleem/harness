1. Capability registry and Typesense

Registry implemented · Typesense worker remains a deployment integration

Keep authoritative skill/tool/agent definitions, immutable revisions, ownership, lifecycle and policy references in an enterprise registry. Produce DeerFlow-compatible configurations/packages from that source. Index searchable descriptions, aliases, entities and approved metadata in Typesense as a derived discovery projection.

  1. Resolve the authenticated user’s permitted capability scope.
  2. Retrieve relevant candidates from Typesense using the prompt and telecom identifiers.
  3. Resolve exact revisions from the authoritative registry and validate policy again.
  4. Load a bounded set through existing skill/tool discovery and selection mechanisms.
  5. Execute in DeerFlow and retain evidence of the chosen versions.

Typesense does not replace authorization, durable memory or the runtime. The extension projects immutable definitions into DeerFlow configuration and exports typesense-documents.json. Bounded lexical skill discovery and MCP routing/deferred schemas remain available. Connecting a Typesense index worker and reauthorized query routing still requires integration.

2. Database schema and telecom semantics

Proposed domain capability

A BQ/Oracle/Postgres connection can supply technical metadata, but not all business joins and meanings. In particular, a shared column name does not prove that two identifiers have the same grain or mapping.

Catalog contentTelecom example
Tables, columns, types and partitionsHourly RAN KPI fact table with site/RAN keys and event-time partition.
Declared and approved relationshipsValidated mapping from site_id to gnodeb_id, with cardinality and validity dates.
Business aliases/definitionsMDN versus subscriber/account identifiers; physical site versus fuze_site_id.
Metric semanticsExact numerator, denominator, time grain, aggregation and missing-data behavior.
Policy and provenancePermitted columns/rows, schema version, approval owner and query receipts.

Nightly metadata refresh should compare snapshots, record schema diffs and invalidate dependent bundles/index entries. Automatically discovered foreign keys and inferred relationships should be distinguishable from approved semantic joins. Build deterministic metadata ingestion and a read-only bounded query interface; expose them through MCP/tools.

DeerFlow’s own Postgres persistence stores application state. Its RAGFlow knowledge catalog manages document retrieval scope. Neither is the proposed business database relationship graph.

3. Answer → draft bundle → reusable skill

Implemented promotion workflow · domain validation requires integration
  1. Capture: consume scoped run evidence and structured data-tool receipts. Include query/logic, approved tables/joins/metrics, input parameters, schema revisions and outputs.
  2. Draft: store a temporary bundle with an expiry, owner and reproduction instructions. Minimize sensitive result data.
  3. User action: a conversation action such as “Create a skill” opens a parameterized draft; it does not silently publish global execution rights.
  4. Validate: run correctness cases, boundary inputs, schema compatibility, dependency checks and the existing skill scanning/review paths.
  5. Publish: record an immutable reviewed revision and its user/team scope in the enterprise registry; project it into supported skill storage.
  6. Discover: update the derived Typesense index and expose the approved capability to authorized agents.

The Create a skill action captures owner-scoped terminal run receipts and hashes into an expiring draft. Users explicitly enter the reusable logic, parameters and DDL references; the sample recipe does not automatically reproduce the answer. Native package scanning, an operator domain validator, independent exact-digest review and atomic immutable publication enforce the promotion stages. Activation and deployment are separate operator actions; Typesense refresh remains external.

4. Keep the adapter small

The enterprise adapter projects one team’s immutable registry snapshot into native configuration, skills and agent templates. The deployed extension checks team membership and registry admission before execution. DeerFlow continues to own planning, tool iteration, middleware and execution. Enterprise services own their domain definitions and review lifecycle.

Use public extension/provider interfaces where appropriate. Record and test any unavoidable host-internal coupling. The extension contract remains pre-1.0 and full-stack contributions are experimental; pin versions and budget for adapter maintenance rather than promising no future change.

5. Example request

Which gNodeBs at Dallas sites had degraded performance last week?

Retrieve candidate workflows and approved table/metric concepts. Resolve the site-to-gNodeB mapping and exact time window. Validate the caller’s data permissions. Execute bounded aggregate queries through the data service. Let a native reviewer check grain and missing intervals. Deliver evidence with schema/metric revisions. If the user promotes the answer, publish the parameterized method and its dependency versions.
