Runtime and embedding

Understand how requests execute, which state survives, and which boundaries an SDK or deployment must preserve.

1. Request-to-answer flow

  1. AdmissionGateway authenticates, resolves ownership, validates trusted context and admits a run.
  2. AssemblyWorker resolves the agent, model, skills, tools, policy and middleware.
  3. ExecutionLangGraph streams model/tool iterations; tools can use MCP, sandboxes or delegated workers.
  4. PersistenceCheckpoints, run status/events, history and artifacts have distinct persistence paths.
  5. DeliveryStream bridge publishes SSE; the UI reconciles live updates with durable history.

Admission, tool authorization, graph state and stream replay are different responsibilities. Preserve each when embedding or exposing new channels.

2. State and durability boundaries

StateRoleDo not assume
CheckpointConversation/graph state for subsequent turns and supported resume pathsEvery subagent or tool has its own resumable checkpoint.
Run repositoryRun lifecycle, ownership and recovery coordinationA recovered run implies external operations were exactly-once.
Event/history repositoryCanonical evidence and conversation replayEvery SQL dependency is captured unless the tool emits it.
Stream bridgeLive delivery and retained event replayAn in-memory bridge works across independent processes.
Batch/MCP/schedule repositoriesDurable subsystem-specific work and leasesTheir retry/cancellation semantics are interchangeable.
MemoryScoped learned facts/summaries and retrievalBusiness metrics or joins become authoritative by being remembered.
Workspace/blob storageFiles, uploads and content storage abstractionsAll artifact producers already use shared blob storage.

SQLite/Postgres application persistence and LangGraph checkpoint providers have separate configuration and migration ownership. The optional blob store is disabled by default and its migration is incomplete in this baseline. Test shared filesystem/object storage behavior before distributing workers.

3. Sandbox behavior

Providers own acquisition, scope, execution and release. Container/cloud providers differ in mount versus upload strategy, shell persistence, cancellation and physical skill views. The local provider exposes host-backed operations and is not a hardened container.

Native subagents share a thread workspace. External ACP processes use a distinct host workspace. Stdio MCP servers run where their command is launched. These three execution environments must be configured separately.

4. Use the existing Python client

Python · direct harness access
from deerflow.client import DeerFlowClient

# Requires configured runtime and model credentials.
client = DeerFlowClient(subagent_enabled=True)
print(client.chat("Summarize the supplied site-performance evidence.", thread_id="example-001"))

for event in client.stream("Explain the evidence limitations.", thread_id="example-002"):
    print(event)

The client does not require a running Gateway or separate LangGraph server. Pass a compatible checkpointer when you need multi-turn state. Direct embedding does not automatically start the Gateway’s schedules, channel services or background MCP task service, or reproduce HTTP admission/authentication.

Several caches/providers/lifecycle hooks are process-scoped. Test isolation before hosting independently configured runtimes inside one process. A small SDK over a shared Gateway is another supported integration approach.

5. Reload and upgrade rules

ChangeExpected operation
Enabled MCP configurationRefresh during subsequent tool assembly; explicit MCP reset also retires sessions.
Skill content/stateRefresh through supported management surfaces; manual cache invalidation is process-local.
Managed subagentRegistry refreshes from storage, with a short cache interval; existing execution remains its own snapshot.
Python extension installed/enabled/upgradedGateway restart; rebuild immutable production image when dependencies change.
Database/checkpointer/stream/scheduler/batch provider fieldsObserve the startup-only registry; do not promise hot reload.

For upstream upgrades, pin the release, run adapter/extension contract tests and rehearse migration with existing state. A successful import is insufficient to prove run recovery, ownership or artifact delivery.
