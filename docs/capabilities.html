1. Orchestration and discovery

CapabilityCurrent foundationActivation / limit
Lead-agent loopLangChain agent on LangGraph; ordered middleware; model/tool iterationsNeeds configured model and eligible tools.
Internal/external custom agentsUser-owned native configurations and SOUL.md; independently running agents integrate through MCP/tools or ACPEnable management API for native CRUD; select a supported interface for separately running agents.
Planning and delegated workPlan mode, native task workers, task status/receipts and shared capacityUltra/request opt-in; agent allowlists and guards apply.
Autonomous goalsThread goal state and bounded continuation/evaluation in the run workerConfigured continuation limits and stopping conditions; does not guarantee task success.
Durable batchesPersistent native item execution, leases and acceptance checksOpt-in startup service with SQLite/Postgres repository.
Internal/external ACP agentsCompatible host subprocesses via invoke_acp_agent, regardless of ownershipSeparate permission, workspace, timeout and capacity semantics.
Tool discoveryDeferred MCP schemas, tool_search and routing hintstool_search is opt-in; no built-in Typesense dependency.
Skill discoveryMetadata catalog, describe_skill and active skill policyskills.deferred_discovery is independently opt-in.
Model behaviorProvider factory, reasoning contract, per-agent settings and admissionProvider packages/credentials/capabilities vary.

2. Context, memory and data access

CapabilityCurrent foundationActivation / limit
Conversation stateLangGraph checkpoints and separate durable history/run eventsChoose supported providers; checkpoint mode compatibility matters.
Context engineeringSummarization, durable context/skill records, tool output budgets and task continuityConfiguration controls features and budgets.
Execution guardsToken/turn budgets, loop detection, output controls and configured guardrail providersEnable and tune the applicable controls; resource limits are separate from authorization.
Long-term memoryMemoryManager with DeerMem, mem0, OpenViking and Honcho backendsBackend-specific capabilities and setup; memory is not a relational semantic catalog.
Knowledge retrievalRAGFlow/LightRAG integrations and supported scope selectionExternal service/configuration required; not automatic table-join understanding.
ProjectsProject instructions, documents and thread/file contextOwnership and archive/read semantics apply.
MCP accessShared/personal connections, sessions, credentials, resource adaptation and task supportTools retain their own service permissions and deployment requirements.

3. Execution and delivery

CapabilityCurrent foundationActivation / limit
Sandbox executionAbstract providers; local, AIO, E2B and community implementationsLocal host execution is not container isolation. Provider guarantees differ.
Files and artifactsThread workspace, uploads, outputs, presentation and workspace change captureShared storage still needs deployment qualification.
Browser toolingConfigured browser/runtime tools and artifactsRequires compatible browser dependencies and sandbox/runtime setup.
SchedulesDurable queued occurrences and non-interactive launchesscheduler.enabled; run admission and timeouts still apply.
Background MCP tasksSubmission/status/cancellation tracking and notification runsEnable task runtime and supported task-toolset/service contracts.
StreamingSSE stream bridge, replay, heartbeat, gap recovery and canonical historyMemory bridge is process-local; Redis supports cross-process streaming.

4. Platform and governance hooks

CapabilityCurrent foundationActivation / limit
AuthenticationGateway identity, sessions/token handling, CSRF and trusted internal callersConfigure deployment auth; never rely on a client-asserted identity.
AuthorizationResource discovery filters, activation/execution gates, configurable provider/RBACEnable and configure policies for actual enterprise resources.
Skill evolution/reviewUser-scoped writes, scanning/history, quality reviewer and CI contractsEvolution is opt-in; shared enterprise promotion is additional work.
ExtensionsPublic API, contributors, services, routers, observers and UI contributionsTrusted operator installation; pre-1.0/experimental contracts require qualification.
ObservabilityTrace context, usage/receipts, Langfuse/LangSmith and optional MonocleExternal tracing setup varies; logging alone is not full audit governance.
Embedded client / hosted APIStandalone harness client and Gateway interfaceLifecycle and admission coverage are different.
ChannelsFeishu, Slack, Telegram, Discord, DingTalk and additional provider implementationsProvider credentials, delivery policies and dedupe must be configured.
Deployment and releaseDocker/Helm, tests, schema migrations and release consistency gatesDoes not establish your enterprise availability or scale target automatically.
