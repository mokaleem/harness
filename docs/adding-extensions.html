1. Use an extension when a skill or MCP is insufficient

An extension can contribute middleware, lifecycle observers, assembly/compaction/system-model observers, services, HTTP routers and full-stack plugin contributions. It is operator-installed Python code with Gateway privileges. Internal and external extensions use the same contract and trust boundary.

For enterprise bundle capture, start with run evidence plus explicit tool receipts; for a promotion button, examine conversation actions in the full-stack plugin contract.

2. Package against the public API

Keep the extension in a separate repository/package. Use deerflow_extension_api and declare every framework you import. The bundled example is a working template:

TOML · package fragment, add build metadata
# pyproject.toml fragment for a separately maintained extension
[project]
name = "deerflow-extension-telecom"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = ["deerflow-extension-api>=0.2.4,<0.3"]

[project.entry-points."deerflow.extensions"]
telecom = "deerflow_extension_telecom:install"

Your package must provide the declared install(registry, config) callable with the @extension(api=..., name=...) marker. Registration happens at startup; services and contributors have their own runtime lifecycle. Follow the complete local example for a working contributor instead of inventing a host import.

The extension API is 0.2.5. Pre-1.0 minor releases may break. Declare the minimum API required by your implementation and qualify upgrades. Direct imports from deerflow.*/app.* are host-internal coupling; avoid them for independently shipped extensions.

3. Install internal or external packages

Use the root extension manager with a trusted local package or supported pinned package source:

Shell · bundled example and lifecycle
make extension-install SOURCE=./examples/deerflow-extension-example
make extension-list
make extension-disable NAME=example
make extension-enable NAME=example

For your team’s package, replace SOURCE with its reviewed source. The manager updates dependencies, snapshots supported local sources and writes the operator-controlled plugins record in config.yaml. Do not add Python imports to API-writable extensions_config.json.

YAML · representative generated record
plugins:
  - name: telecom
    package: deerflow-extension-telecom
    use: deerflow_extension_telecom:install
    enabled: true
    required: false
    config:
      environment: development

Restart the Gateway after every install/upgrade/enable/disable/remove. Rebuild production images when the installed set changes. required: true makes a load failure abort startup; use that only for contributions that must be present for your deployment.

4. Reuse the supported contribution kinds

ContributionExample enterprise use
MiddlewareAttach query receipts or apply an additional approved execution policy.
Task lifecycle / agent assembly observersRecord run outcomes, effective capabilities and policy versions.
System model / compaction observersObserve model operations and context lifecycle.
Service and HTTP routerRun indexing/evidence workers and expose draft-bundle APIs.
RunEvidenceReaderRead scoped run status/events without reaching into internal SQL tables.
Full-stack pluginAdd a conversation action or workspace page, subject to its experimental contract.

Evidence pagination needs idempotent consumers; the changed-run interface has no deletion tombstones. If you own extension database tables, follow the separate migration ownership/table-prefix rules. Frontend extension modules are trusted code, not a JavaScript security sandbox.

5. Verify and upgrade

  1. Test registration/contributors against stand-in contracts in the extension repository.
  2. Verify startup diagnostics and test both lead and subagent paths when contributing middleware to both scopes.
  3. Check request-bound principal/evidence access with different users.
  4. Rehearse disabled and failed startup behavior, service cleanup and a pinned upgrade.
  5. Keep adapter/extension compatibility tests independent from your enterprise business logic.
