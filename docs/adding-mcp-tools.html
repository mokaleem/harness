Add MCP tools

Add internally owned and externally supplied MCP tools, whether their server is a local process or a remote service.

Internal and external MCP tools

OriginTelecom exampleConnection mechanism
InternalYour company’s approved BigQuery query/catalog MCPCorporate HTTP/SSE endpoint or reviewed stdio executable.
ExternalVendor RAN diagnosis MCP or an open-source MCP packageVendor HTTP/SSE endpoint or reviewed stdio executable.

Choose origin and transport separately. Remote does not mean external: an internal service can be hosted elsewhere in your enterprise. Shared versus personal installation determines configuration/credential ownership, not the origin of its tools.

1. Build an internal MCP server

Create a separately owned service/environment. This small stdio fixture proves connectivity; it returns demo metadata and does not query BigQuery.

server.py · connectivity fixture
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("telecom-catalog")

@mcp.tool()
def get_site_metadata(site_id: str) -> dict:
    """Return demo catalog metadata for a site_id; not production data."""
    return {"site_id": site_id, "source": "demo-fixture", "technology": "5G"}

if __name__ == "__main__":
    mcp.run(transport="stdio")

Install mcp in that service’s own locked Python environment. For a stdio server, stdout is protocol traffic: write application logs to stderr. A production query server should validate identity, resource permissions, SQL/query bounds and cancellation, and return table/query/schema evidence.

2. Register the server

Merge the server under root extensions_config.json → mcpServers. For a local process, use the absolute executable and script paths visible to the Gateway:

JSON · shared stdio MCP entry
{
  "mcpServers": {
    "telecom-catalog": {
      "enabled": true,
      "type": "stdio",
      "command": "/opt/telecom-mcp/.venv/bin/python",
      "args": ["/opt/telecom-mcp/server.py"],
      "tool_name_prefix": true,
      "session_init_timeout": 60,
      "tool_call_timeout": 60,
      "description": "Internal telecom site catalog"
    }
  }
}

On native Windows, use your service’s .venv/Scripts/python.exe and an absolute script path. In Docker, those paths and the executable must exist inside the Gateway container. A stdio process is not automatically executed in DeerFlow’s sandbox.

An internal HTTP service uses the same transport mechanism as an external one:

JSON · replace the illustrative endpoint
{
  "mcpServers": {
    "telecom-data": {
      "enabled": true,
      "type": "http",
      "url": "https://telecom-data.example/mcp",
      "headers": {"Authorization": "$TELECOM_MCP_AUTH_HEADER"},
      "description": "Approved site, RAN and performance queries",
      "routing": {
        "mode": "prefer",
        "priority": 80,
        "keywords": ["site_id", "gnodeb_id", "performance", "BigQuery"]
      }
    }
  }
}

The environment variable should hold the complete header value, including any required Bearer prefix. $VAR references resolve from the Gateway environment. A URL must be reachable from that runtime; container localhost refers to the container itself. HTTP/SSE ordinary calls use transport-level timeouts; tool_call_timeout explicitly bounds stdio calls and durable-task calls.

3. Add external MCP tools

  1. Obtain its actual MCP endpoint or reviewed command/package release. Pin subprocess package versions instead of using a moving latest version.
  2. Register its http, sse or stdio entry with the provider’s supported authentication.
  3. For user-owned connections, use the Personal MCP settings/API rather than putting every user’s secrets in shared config. The personal configuration API is rooted at /api/mcp/personal/config.
  4. Inspect the discovered tools and account access before exposing the connection to an agent. A remote provider’s capability description is not an authorization policy.
JSON · external provider, replace the illustrative endpoint
{
  "mcpServers": {
    "vendor-ran-analyzer": {
      "enabled": true,
      "type": "http",
      "url": "https://ran-vendor.example/mcp",
      "headers": {"Authorization": "$VENDOR_RAN_AUTH_HEADER"},
      "tool_name_prefix": true,
      "description": "Vendor-provided RAN analysis tools"
    }
  }
}

Merge this entry alongside your internal servers. Replace the placeholder with the vendor’s supported endpoint and configure the complete authorization header in the Gateway environment. For an externally supplied stdio package, use the internal stdio entry’s shape with the reviewed vendor executable and arguments.

Shared entries can use user_auth for user-mapped headers, or headers_from_context for supported request credentials. Follow the local MCP guide for these exact carriers; do not assume a browser-supplied identity becomes trusted.

4. Control tool discovery and selection

YAML · config.yaml
tool_search:
  enabled: true
  auto_promote_top_k: 3

With deferred discovery, full MCP schemas become visible after search or routing promotion. Routing keywords are soft hints. Agent mcp_plugins selects stable installation IDs; obtain the actual IDs from the installed catalog rather than guessing them from display names. Authorization still determines execution access.

Prefixes avoid collisions. For the stdio fixture, expect a name like telecom-catalog_get_site_metadata; verify the actual exposed name before using it in a skill/subagent allowlist.

5. Verify and reload

  1. Inspect the MCP configuration in Settings or GET /api/mcp/config.
  2. Run a prompt that asks for demo site metadata and confirm the exact tool name, arguments and fixture source.
  3. Test an unavailable endpoint and invalid credentials; errors should be bounded and intelligible.
  4. Check that user-scoped connections and sessions do not cross account boundaries.
  5. Changing enabled MCP configuration refreshes the relevant cache on subsequent assembly. POST /api/mcp/cache/reset explicitly retires cached tools and pooled sessions. Installing executables or changing deployment environments may still require rebuild/restart.
Long-running reports

For services exposing submit/status/cancel tools, configure task_toolsets and enable the durable MCP task runtime with its repository. This is a separate workflow from an ordinary tool call; see the example configuration and durability guide.
